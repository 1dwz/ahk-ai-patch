# What a release artifact is expected to contain.
#
# Read by BOTH tools/build.ps1 (to warn when a build's output drifts) and the CI
# verify job (to fail when it does).  Keeping the list in one place is the point:
# a second hard-coded copy in the workflow already caused a red run, when a doc
# was added to dist/ and the workflow list did not know about it.
#
# Rules:
#   - one entry per line, file name only (artifacts are flat)
#   - <arch> is replaced with 64 for the x64 artifact, 32 for Win32
#   - '#' starts a comment
#
# Everything listed must be produced by tools/build.ps1 -OutDir.  Nothing that
# is loadable at runtime may appear here: no DLL, no CA bundle, no sidecar
# config.  cmd tests passing with only the exe and a script present is the whole
# promise this file guards.
#
# This is the entire product of the repository: one interpreter per
# architecture, both customisations (/AI and the OutputDebug console mirror)
# compiled in.  The installer, the generated API reference and the Debug build
# were removed on purpose -- a payload file that is not an interpreter is a
# regression against this list, not a to-do item.
AutoHotkey<arch>.exe
